# Ключевые инженерные решения

## Получение сообщений

Microsoft Graph опрашивается каждые 20–30 секунд. Полный обход выполняется
периодически, а уникальный ключ сообщения не допускает повторной вставки.

## Группировка

Сначала применяются проверяемые правила: тред, точный email/телефон,
противоречащие идентификаторы и явные фразы нового контакта. LLM вызывается
только для неоднозначного остатка. При сомнении сообщение остаётся без лида.

`group_key_registry` сохраняет связь исходных сообщений со стабильными
`group_key` и `crm_external_key`. Поэтому `grouping_worker.py --rebuild`
может пересоздать производные строки, не меняя идентичность лида в CRM.

## Извлечение

LLM предлагает структуру и evidence, но окончательное решение принимает код.
Email с гомоглифами/вероятной опечаткой, должность без явного названия роли и
приоритет без прямого указания не отправляются в CRM. Partner допускается
только при явном партнёрском/дистрибьюторском/реселлерском/интеграторском
сигнале либо прямом намерении продавать или внедрять продукт клиентам.

## Bitrix24

Перед созданием проверяются локальный CRM ID, стабильный внешний ключ и точные
телефон/email через поиск дублей. После `crm.lead.add` ID сохраняется до
добавления комментариев, поэтому сетевой сбой не создаёт второй лид.

## Безопасность

Секреты читаются только из `.env`, который исключён из Git. В логах остаются
только технические ID, статусы и коды ошибок; тела сообщений, контакты,
токены и webhook URL не печатаются.
